# Office Internal Maintenance Web Application Architecture Design

## 1. Overview
This document describes the proposed architecture for the Office Internal Maintenance Web Application, designed to efficiently manage employee maintenance requests, admin responses, and tracking, as outlined in the requirements.

## 2. High-Level Architecture
The application will follow a modern, layered web architecture with clear separation of concerns:
- **Frontend (Client)**: React-based SPA (Single Page Application)
- **Backend (API Server)**: Java (JDK 21) RESTful API
- **Database**: Relational DB (e.g., PostgreSQL)
- **File Storage**: For attachments (e.g., local, S3, or company file server)
- **Authentication**: JWT-based, integrated with company email/SSO
- **Notifications**: Email and/or in-app

## 3. Main Components
### 3.1 Frontend (React)
- User authentication and role-based access
- Request submission and tracking UI
- Admin dashboard and management UI
- Notification display (in-app)
- Responsive design for desktop/mobile

### 3.2 Backend (Java JDK 21, Spring Boot)
- RESTful API endpoints for all business logic
- Authentication and authorization (JWT, role-based)
- Request management (CRUD, status updates, assignment)
- File upload/download endpoints
- Notification triggers (email, in-app)
- Audit logging
- Reporting endpoints

### 3.3 Database (PostgreSQL)
- Users, roles, and permissions
- Maintenance requests and status history
- Attachments metadata
- Audit logs
- Configurable categories/locations

### 3.4 File Storage
- Stores uploaded attachments (photos, resolution files)
- Can be local or cloud-based, depending on deployment

### 3.5 Notification Service
- Sends email notifications (SMTP or integration with company mail)
- Supports in-app notifications (WebSocket or polling)

### 3.6 Authentication Provider
- Integrates with company SSO or email-based login
- Issues JWT tokens for session management

## 4. Data Flow
1. **User logs in** via company SSO/email; receives JWT token.
2. **Employee submits request** via React UI; frontend calls backend API with JWT.
3. **Backend validates, stores request** in DB, saves attachments to file storage.
4. **Admin views dashboard**, assigns/updates requests via API.
5. **Status changes** trigger notifications (email/in-app) to relevant users.
6. **Employees track status** and receive updates.
7. **Reports** generated by backend and delivered to admin UI.

## 5. Technology Stack
- **Frontend**: React, TypeScript, Axios/Fetch, Material UI/Ant Design
- **Backend**: Java JDK 21, Spring Boot, Spring Security, JPA/Hibernate
- **Database**: PostgreSQL (or compatible RDBMS)
- **File Storage**: Local filesystem, S3, or company file server
- **Notifications**: JavaMail, WebSocket (Spring), or third-party service
- **Authentication**: JWT, Spring Security, SSO integration

## 6. Deployment Considerations
- **Containerization**: Use Docker for backend and frontend
- **CI/CD**: Automated build, test, and deployment pipelines
- **Environment Configs**: Separate configs for dev, test, prod
- **Scalability**: Stateless backend, scalable DB, and storage
- **Security**: HTTPS, input validation, OWASP compliance
- **Monitoring**: Application and infrastructure monitoring (e.g., Prometheus, Grafana)

## 7. Assumptions
- Internal deployment (company network or private cloud)
- All users have company email/SSO
- File storage and email infrastructure are available
